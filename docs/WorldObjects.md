> В актуальной игровой сцене перенос добавляет шаг плана, а подтверждённая Cell изменяется только
> после исполнения хода. При запуске сначала выбирается Host/Client. Сцена и планы входят в WorldState v3;
> подробности: [Планирование хода](TurnPlanning.md). Описанный ниже прямой Commit остаётся поведением
> самостоятельного World/View без внедрённого IWorldInteraction и покрывается отдельными тестами.
# Объекты мира: Game и Data

В `Assets/Scenes/Test.unity` игрок и две стопки коробок привязаны к `WorldState`.
ЛКМ перетаскивает объект с привязкой к ближайшей ячейке. При отпускании изменяется
модель; Escape, потеря фокуса, выключение объекта или входящее изменение его позиции
отменяют перенос. По умолчанию панель прежнего тестового инвентаря открывается клавишей
**I**, отмена — **Escape**. Эти привязки теперь задаются игровыми действиями
`Inventory.Toggle` и `Cancel`; переназначение доступно по **F1** или кнопке
«Управление». Подробности: [InputSystem.md](InputSystem.md).

## Границы системы

Общая механика находится в `Assets/Shared/Scripts/Systems/WorldObjectSystem`.
Она не знает о сцене, камере, префабах, игроках и мебели. Конкретная интеграция —
в `Assets/Scripts/World`: `Data` содержит состав мира, `Game` — его представления и ввод.
Это разделение следует разделу «Обязательные критерии для будущей разработки»
в корневом `project_context.md`.

```text
Shared: ObjectData (TrackableNode)
          ├── ServerCore: PlayerData
          └── ServerCore: FurnitureData

WorldState → Players / Furniture → ObjectData.Cell
                                      ↓ Changed / Patched
GridProvider ← UnityGridSpace ← WorldObjectView → Transform
                                     ↑
                       GridObjectDrag → GridMoveSession
```

`PlayerData` не связан с тестовым `Inventory.PlayerContext`: последний по-прежнему
управляет навыками и чертежами инвентарного демо. Их интеграцию можно добавить отдельно.

## Что хранится в Data

| Поле | Смысл |
|---|---|
| `ObjectData.Id` | Постоянный уникальный ID экземпляра, например `scene-player` |
| `ObjectData.DefinitionId` | Ключ вида объекта/префаба, например `player` |
| `ObjectData.Cell` | Одно `Sync<GridCoordinate>` с целыми `X`, `Y`, `Z` |
| `WorldState.Players` | Типизированный `SyncList<PlayerData>` |
| `WorldState.Furniture` | Типизированный `SyncList<FurnitureData>` |

В Data нет `GameObject`, `Transform`, `GridCell`, мировых координат и ссылки на prefab.
`GridCoordinate` — неизменяемое значение с равенством по компонентам. Одно перемещение
создаёт один путь, например `Players.[0].Cell`, со значением `{"X":2,"Y":0,"Z":5}`.
Повторное присваивание той же координаты не создаёт локальный патч.

`X/Z` отсчитываются от origin `GridProvider`, `Y` — округлённый индекс мировой высоты
в размерах клетки, **не порядковый номер этажа**. Фактическая высота поверхности может
отличаться от `Y * CellSize`; поэтому View разрешает адрес через
`GridProvider.GetCellAt(Vector3Int)` и использует реальный центр найденной ячейки.
Подробности геометрии: [GridSystem.md](GridSystem.md).

Сейчас используется одна сетка. На всех клиентах должны совпадать её origin,
CellSize и набор адресов/поверхностей. Для нескольких карт/сеток добавьте в контракт
идентификатор сетки и версию её геометрии. Unity instance ID нельзя использовать как сетевой ID.

## Жизненный цикл

1. `WorldDataHolder` создаёт один `WorldState` при первом обращении либо `Awake`.
   `Start` не заменяет модель: сеть и представления всегда получают одну ссылку.
2. `WorldSceneController.Start` проверяет каталог префабов и уникальность SceneId.
   Если мир ещё не инициализирован и пуст, он создаёт Data для объектов из `Scene Objects`,
   выбирая ближайшую клетку к точке опоры каждого объекта.
3. Начальная привязка перемещает объект точно на ячейку. `WorldObjectView.Bind`
   подписывается и на локальный `Cell.Changed`, и на входящий `Cell.Patched`.
4. Во время drag `GridMoveSession.Preview` проверяет адрес и правило. View временно
   двигается на выбранную клетку; Data и сеть остаются без изменений.
5. При отпускании кнопки `Commit` повторяет проверки и один раз записывает Cell.
   Обычная подписка View применяет окончательную позицию. Брошенный на UI или далеко
   от доступных ячеек объект возвращается в положение из Data.
6. Входящий патч обновляет View без обратной отправки. Если в это время шёл drag,
   он отменяется: старое предварительное положение не перезапишет новые данные.
7. Добавление/удаление Data и загрузка snapshot помечают состав сцены для сверки в
   `LateUpdate`. Существующие View сопоставляются по Id; перемещение не пересоздаёт их.
   После snapshot прежний View перепривязывается к новому экземпляру Data с тем же Id.
8. При удалении из Data View отписывается, выключается и уничтожается. При уничтожении
   контроллера все подписки снимаются. Полностью пустой snapshot не заселяет сцену заново.

## Назначение компонентов

| Компонент | Ответственность / точка расширения |
|---|---|
| `IGridPositioned` | Минимальная модель с изменяемой координатой; можно реализовать без SyncSystem |
| `IGridSpace` | Проверка существования адреса; тесты используют подменную сетку |
| `GridMoveSession<T>` | Preview → Commit/Cancel; проверка устаревшего исходного положения; дополнительное правило-делегат |
| `ObjectData` | Общие Sync-поля объекта, без Unity-зависимостей |
| `WorldState` | Конкретные коллекции игры и версионированный полный snapshot |
| `WorldDataHolder` | Владелец единственного состояния сцены |
| `UnityGridSpace` | Перевод GridCoordinate ↔ GridSystem |
| `WorldObjectView<T>` | Общая привязка, позиционирование и создание типизированной Data |
| `PlayerObjectView`, `FurnitureObjectView` | Выбор коллекции для нового объекта |
| `GridObjectDrag` | EventSystem-ввод, проекция курсора на поверхность, отмена и подтверждение |
| `WorldSceneController` | Каталог префабов, начальное наполнение, согласование состава сцены с Data |
| `WorldDemoControls` | Только клавиша I и строка подсказки тестовой сцены |
| `WorldCameraFocus` | Стабильный фокус камеры по ID и подтверждённой Cell; preview не двигает камеру вслед за объектом |
| `WorldObjectViewEditor` | Отображение текущих Data.Id и Cell в Inspector во время Play Mode |

Проекция курсора пропускает коллайдеры переносимых объектов. При отсутствии поверхности
используется горизонтальная плоскость на исходной высоте. `Surface Mask` позволяет
выбрать слои пола/ландшафта; `Snap Distance` задаёт допустимое удаление от центра клетки.
Сетка статическая: перенос объектов не перестраивает её и не меняет граф соседей.
Камера ссылается на `World/Player Camera Focus`, а не на внутренний Transform FBX.
При удалении игрока фокус остаётся на последней позиции; при появлении того же Id
снова начинает следовать за данными. `CameraManager` также безопасно переживает
временное отсутствие фокуса при выгрузке сцены.

## Новый экземпляр существующего вида

1. Поместите prefab из `Assets/Prefabs/World` в сцену.
2. На экземпляре задайте уникальный `Scene Id`. В самом prefab этот параметр пустой.
3. Добавьте View в массив `WorldSceneController.Scene Objects`.
4. Проверьте, что соответствующий prefab уже есть в `Prefabs` контроллера, а под
   объектом существуют ячейки GridSystem.

Дублирование экземпляра Unity копирует его SceneId — измените его вручную.
Повторяющийся ID выдаёт явную ошибку при старте.

## Новый вид мебели / новый префаб

Для ещё одного вида мебели новый класс не нужен:

1. Создайте GameObject с 3D-моделью, Collider и `FurnitureObjectView`.
   `GridObjectDrag` добавится автоматически. Не используйте динамический Rigidbody,
   который будет одновременно с Data управлять Transform.
2. Задайте уникальный `Definition Id`, например `furniture.table`.
3. Задайте `Anchor Local` — точку опоры в локальных координатах корня. Она попадёт в
   центр ячейки. Это позволяет сохранить исходный pivot и scale импортированной модели.
4. Сохраните prefab в Game-части проекта и добавьте его View в каталог `Prefabs`.
5. Для начального экземпляра выполните предыдущий раздел. Для runtime-spawn создайте
   `FurnitureData`, заполните Id/DefinitionId/Cell и добавьте в `state.Furniture`.
   Контроллер сам создаст View в `Spawned Objects Root`.

Id и DefinitionId назначайте до добавления в коллекцию и сохраняйте постоянными.
Для runtime Id подходит `Guid.NewGuid().ToString("N")`; для исходных сценовых объектов
нужны заранее сохранённые ID, одинаковые в копиях сцены. Обёртки Sync/List — readonly:
изменяйте их содержимое, не заменяйте экземпляры после подключения подписок.

## Новые правила и типы Data

Ограничение мебели можно добавить наследованием от `FurnitureObjectView` и
переопределением `ValidateMove(ObjectData data, GridCoordinate target)`:
верните `null`, если перенос разрешён, либо причину отказа. Правило проверяется
при предварительном выборе и повторно при подтверждении. В нём можно обращаться
к сервису занятости, правам владельца, габаритам или другим правилам игры.
Общая механика перемещения при этом не меняется.

Для нового семейства объектов:

1. Создайте наследника `ObjectData` в Game/Data с публичным конструктором без аргументов.
2. Добавьте его типизированный SyncList в `WorldState`, перечисление в `Objects` и
   восстановление списка в `ApplySnapshot`. Изменение схемы требует явной версии/миграции.
3. Наследуйте `WorldObjectView<YourData>` и реализуйте `AddToWorld`, выбрав этот список.
4. Настройте prefab и каталог. В drag, сетевой сериализации и согласовании View
   добавлять switch по типам или enum не требуется.

Вне Unity используйте `GridMoveSession<T>` с любой реализацией `IGridPositioned`,
`IGridSpace` и необязательным делегатом правила. Это же подходит для команд ИИ.

## Snapshot, сеть и совместимость

Схема **v2** намеренно заменяет старые `WorldState.Boxes` / `BoxData.Position: Vector2Dto`.
Пользовательское наполнение старого тестового мира удалено по задаче. Новый `WorldState`
находится в сборке `ServerCore.World`, namespace `ServerCore.World.Data`.
Неиспользовавшиеся в сценах старые `BoxDataView` и корневой demo `GameManager` удалены;
одноимённый Shared GameManager не менялся. GUID перенесённого `WorldDataHolder` сохранён.

Snapshot содержит `$schema: 2`. Загрузка другой версии отвергается до изменения мира;
автоматического преобразования старых XY в ячейки нет, потому что оно требует выбора
сетки и поверхности. Для этой демонстрации создайте новый мир из сцены. Если старые
сохранения нужны позже, реализуйте отдельную миграцию v1 → v2 с этими зависимостями.

`ApplySnapshot` заменяет обе коллекции, даже когда в снимке нет элементов. Представления
подписываются на `Sync.Cell.Patched` напрямую: SyncList распространяет изменения
элементов `Changed`, но не все вложенные `Patched`.

Существующему `DmNetworkController` нужно назначить **тот же WorldDataHolder**, что и
`WorldSceneController`. `GameClient` получает `holder.WorldState`; его `Update` применяет
очередь на главном потоке. Перед подключением сети дождитесь инициализации сцены.
Обе стороны должны работать на схеме v2; версия snapshot не делает старые patch-пути совместимыми.

Текущий перенос — свободное размещение на существующих ячейках. Он не требует пути,
не запрещает перекрытие предметов и не резервирует площадь под крупную мебель.
Такие ограничения добавляются через правило перемещения. Авторитетная серверная
проверка команд и разрешение конфликтующих одновременных изменений состава списков
не входят в этот шаг: существующий протокол адресует элементы коллекций по индексу.

## Проверка

EditMode-тесты: `Assets/Tests/Editor/World/WorldDataTests.cs` проверяют транзакцию переноса,
альтернативную модель/сетку, JSON-патчи, отсутствие эха, добавление/удаление объектов,
полную замену снимка и отказ старой схеме. `WorldSceneTests` проверяет самостоятельность
префабов и через EnterPlayMode — привязку сцены, drag, входящий патч,
перепривязку snapshot, удаление мира и создание View из новой Data.

`WorldNetworkProcessProbe` запускается через `-executeMethod` в двух отдельных
Unity-процессах с параметрами `-worldProbeRole host|client`, `-worldProbePort PORT`,
`-worldProbeReport ABSOLUTE_PATH`. Сначала запустите host, затем client, используя
разные копии проекта. Проверка работает только на loopback и проверяет snapshot,
двусторонние перемещения и добавление/удаление коллекций через настоящий TCP.

Однократный editor-инструмент `Tools → World → Set up Test scene` создаёт начальную
конфигурацию только при отсутствии `WorldSceneController`. Он не перезаписывает
уже настроенную сцену. Геометрия коробок сохранена в `Assets/Prefabs/World/Meshes`;
варианты сохраняют исходные сценовые объекты.

Проверено 2026-09-28 в Unity 6000.6.3f1: **75/75 тестов** общего набора прошли
(`Logs/World/final-results.xml`). Отдельные host/client-процессы завершили TCP probe
с PASS (`Logs/World/network-host-2.txt`, `network-client-2.txt`). Контрольный кадр
сцены сохранён в `Logs/World/world-preview.png`. Проверки выполнялись в изолированных
копиях проекта; итоговые код, сцена и prefab-ассеты совпадают с рабочими файлами.
