# Editor-authored inventory workbenches and live player context

User asks to retain their CampfireWorkbench and move static appearance, recipes and slot rules into Editor, provide scene PlayerContext implementing IPlayerContext plus runtime controls, add an infinite catalog discovered from Assets/Data, and keep stations current when skills/blueprints change (including progress earned during crafting). Update Russian comments and guide.

## Design
- ItemDefinition/ItemTag keep existing GUIDs, filenames and user content. Preserve the user's Test scene and all prefab layouts; migrate component data in place.
- CraftingRecipeDefinition assets contain identity/name, ingredient item/tag filters and quantities/optional slot index, required blueprint key and skill levels, output definition/quantity, optional level/quality stats, and optional skill experience reward. No item/skill enum. A configured station exposes recipe assets and existing SlotSettings in Inspector. GunWorkbench and CampfireWorkbench become thin script-compatible examples using these fields.
- Static slot placeholders and text belong to inspector data/authored UI. View refresh changes item-dependent values only; configurable messages cover dynamic statuses. Keep functional slot predicates separate from hints.
- IObservableInventoryContext exposes Changed. IPlayerContext extends it with Level, GetSkillLevel(string), HasBlueprint(string), AddSkillExperience(string,int). PlayerContext is a scene MonoBehaviour with editable serializable skill/blueprint lists, level, setters and experience progression. Debug view edits this same provider.
- Generic CraftingStationComponent subscribes to observable context. Idle updates immediately refresh preview; updates during a protected commit are queued and flushed after completion/before subsequent actions. Stale preview drags are rejected. OnDestroy unsubscribes; disabled UI must not prevent model freshness. Context providers are replaceable through the interface.
- ConfiguredCraftingStation : CraftingStationComponent<IPlayerContext> resolves an explicitly assigned MonoBehaviour provider or finds an active IPlayerContext in its scene. No per-station player snapshot defaults. Successful recipes may award configured experience only once; auto refresh then unlocks new options. Committed output is immutable and remains unchanged by later context updates.
- ItemCatalog asset holds all ItemDefinition assets (including derived types) under Assets/Data. Editor scan refreshes on asset changes and before builds; runtime uses saved references. InfiniteCatalogView uses Shared InfiniteItemStorage materialization, a slotted display and ordinary validated target addition; templates never disappear and issued ItemIds are unique. Incoming drops are refused.
- Add a context panel and catalog to the existing demo prefab, preserve the user's authored workbenches. Integrate without overwriting Test scene objects/overrides.

## Contracts
IObservableInventoryContext { event Action Changed; }
IPlayerContext : IObservableInventoryContext { int Level {get;} int GetSkillLevel(string id); bool HasBlueprint(string id); void AddSkillExperience(string id,int amount); }
PlayerContext fields: InitialLevel (or inspector backing property Level), Skills List<PlayerSkill>, Blueprints List<PlayerBlueprint>; PlayerSkill: Id, DisplayName, Level, Experience, ExperiencePerLevel; PlayerBlueprint: Id, DisplayName, Known. Mutators: SetLevel(int), SetSkillLevel(string,int), SetBlueprint(string,bool), AddSkillExperience(string,int).
PlayerContextView fields: PlayerContext Source, InputField LevelInput, PlayerSkillControl[] Skills, PlayerBlueprintControl[] Blueprints. Controls: string Id, InputField ValueInput / Toggle KnownToggle, optional Text Label. Bind events and refresh without callback loops.
ConfiguredCraftingStation public CraftingRecipeDefinition[] Recipes; MonoBehaviour ContextSource. It inherits existing Slots and SlotCount. ConfiguredCraftingStation.ReadPlayerContext resolves/returns current IPlayerContext; generic base handles subscription and safe refresh.
CraftingRecipeDefinition public fields Id, DisplayName, RecipeInput[] Ingredients; ItemDefinition Result; int ResultQuantity=1; bool UsePlayerLevel; int Quality=1; string RequiredBlueprint; SkillRequirement[] RequiredSkills; string RewardSkill; int RewardExperience. RecipeInput: ItemDefinition[] Items, ItemTag[] Tags, int Quantity=1, int SlotIndex=-1. SkillRequirement: string Id,int Level.
ItemCatalog public ItemDefinition[] Items; editor ItemCatalogBuilder.Refresh() scans Assets/Data and stores Assets/Resources/Inventory/ItemCatalog.asset.

## Verification
Editor-only authored recipes/rules; legacy Campfire recipe variants preserved; static inspector placeholders survive Refresh; skill and blueprint changes refresh multiple stations; context changes during commit unlock next recipe safely; stale drag rejected; created result remains stable; infinite repeated drag creates unique identities and rejects full/filter targets without losing templates; auto discovery includes user data and derived definitions; prefab/scene references and visual layout verified in Unity.
