# План: контексты ввода и стопки

Спецификация: `docs/superpowers/specs/2026-10-01-input-contexts-design.md`.
Пользователь одобрил реализацию без дальнейших согласований. Выполнение последовательно; отдельная проверка кода после интеграции.

1. Сохранить исходные версии затрагиваемых каталогов, синхронизировать изолированную копию `.utmp/WorldObjectsUnity`. В ней выполнять изменения и Unity tests; в рабочий проект переносить только файлы задачи после проверки исходных хешей.
2. Добавить воспроизводящие тесты на передачу необработанного действия нижнему контексту и объединение одинаковых стопок. Запустить тесты: ожидаются отказы по этим двум сценариям при успешной компиляции.
3. В Shared реализовать управляемую двусвязную цепочку, дескрипторы жизненного цикла, обработку действий и прокрутки до обычных подписчиков. Сохранить совместимость используемых методов InputContextManager. Проверить снятие среднего узла, исключение при входе, возврат и изменения цепочки во время dispatch.
4. В Shared добавить IStackableItem<TItem> и операции разделения/слияния в SlottedInventory. В ServerCore реализовать контракт ItemInstance и равенство CraftedItemStats. Проверить сохранность количества, лимиты, идентификаторы, правила, TryAdd и крафт.
5. Расширить захват переноса InventoryView запросом количества; обновить каталог, результат крафта и drag controller. Подключить InventoryInputCoordinator и ContextScrollRect к prefab-ам. Проверить жесты и переходы на настоящих UI-объектах.
6. Обновить руководства, выполнить полный EditMode suite (включая UnityTest переходы PlayMode), отдельный обзор изменённых файлов и исправления найденных ошибок. Перенести проверенные исходники/метаданные/prefab-ы в рабочий проект.

Интерфейсы: InputContextChain.DispatchAction(string), DispatchScroll(Vector2); Enter(InputContext) возвращает IDisposable. InputManager подключает цепочку к Router. IStackableItem<TItem> описывает Quantity, MaxStack, CanStackWith, WithStack(quantity, itemId). SlottedInventory.TryMoveTo получает необязательное quantity; старые вызовы сохраняются. InventoryView.CaptureTransfer получает количество при исполнении отложенного переноса.

Проверка выполняется Unity 6000.6.3f1 в `.utmp/WorldObjectsUnity`, результаты в `Logs/InputContexts`. Тесты сначала подтверждают отсутствие поведения, затем проверяют реализацию. Существующий открытый редактор и его Library не затрагиваются.

Особое внимание обзора: повторный ввод из callbacks, закрытие UI во время drag, совпадение идентификаторов при merge, неизвестные параметры экземпляра, целостность правил обеих моделей, повторная прокрутка EventSystem, переназначенное колесо и модальный захват клавиши.

## Выполнение и проверка

- Все шаги выполнены в изолированной Unity-копии. С исходными версиями сравнивались хеши; при переносе 45 файлов конфликтов и расхождений не обнаружено.
- Первые воспроизводящие проверки: 3 ожидаемых отказа (передача вниз, поглощение, слияние).
- Отдельный обзор выявил очистку ресурсов после неудачного Init, переключение на другой источник при неудачной замене корня, скрытие корня источника и несколько экземпляров UI. Для них получены 5 ожидаемых отказов, затем успешный прогон после исправлений.
- Неизвестные подклассы ItemInstance требуют явного разрешения слияния. Проверка потери дополнительных параметров сначала падала, после изменения прошла.
- Миграционное решение: тест меню наблюдает действие камеры через пропускающий контекст, поскольку MainContext теперь поглощает его до обычного Performed. Настоящая реакция камеры сохраняется.
- Координаторы нескольких prefab-ов регистрируются в одной InventoryInputSession на источник ввода; это сохраняет согласованную глубину цепочки и маршрутизацию прокрутки.
- Итог: Unity 6000.6.3f1, полный EditMode suite с PlayMode integration — **116/116**, `Logs/InputContexts/verified.xml`. Отложенных замечаний обзора нет. Предупреждения устаревшего FindFirstObjectByType в WorldSceneSetup существовали ранее.
- Реализация перенесена в рабочий проект, существующие сторонние изменения сохранены. Сетевой протокол не изменялся.
