# Процедурные панели и дерево вкладок

Откройте `Assets/Scenes/Test.unity` и нажмите **I** (`Inventory.Toggle`).
Появятся два независимых корневых окна: слева инвентарь, каталог и параметры игрока;
справа оружейная мастерская и костёр. На узком экране окна располагаются друг под
другом. Повторное нажатие скрывает оба окна. Модели и предметы сохраняются.

Закладки содержат иконку и текст. Если вкладок больше, чем помещается в полосе,
полосу можно прокручивать колесом или тянуть мышью. При переносе предмета наведите
его на нужную закладку: страница откроется, после чего можно завершить drop в ячейку.
Это работает и для переноса из каталога в инвентарь внутри одного окна.

## Фасад TabPanel

`Shared.UI.TabPanel` — единая точка работы с панелью. Универсальная механика лежит
в `Assets/Shared/Scripts/Systems/TabSystem`, сборка `Shared.UI`. Она не знает об
инвентарях, рецептах, действиях ввода, WorldState или сцене примера.

```text
Canvas
└─ Workspace (обычная раскладка, не TabPanel)
   ├─ InventoryTabs (корень TabPanel)
   │  └─ Body
   │     ├─ InventoryPanel (страница)
   │     ├─ InfiniteCatalog (страница)
   │     └─ PlayerContextPanel (страница)
   └─ WorkbenchTabs (корень TabPanel)
      └─ Body
         ├─ GunWorkbench (страница)
         └─ CampfireWorkbench (страница)
```

Ближайший предок с `TabPanel` становится родителем. Несколько соседних страниц
образуют один набор закладок родителя; видна одна выбранная страница. Любая из них
может содержать собственные страницы, так что число уровней не ограничено кодом.
Обычные промежуточные RectTransform не являются уровнями дерева.

Панель без предка `TabPanel` — корневая: она сохраняет свои anchors и размеры,
может стоять рядом с другими корнями и управляется как стандартный UI GameObject.
Не добавляйте TabPanel на общий Canvas, если окна под ним должны быть видны одновременно.

## Новый корень или дочерняя страница

1. Разместите `Assets/Prefabs/UI/TabPanel.prefab` под Canvas. Нужны GraphicRaycaster
   и EventSystem. Размеры корня задайте через RectTransform или родительский LayoutGroup.
2. Настройте **Caption**, **Icon**. Они показываются в закладке родителя.
3. Разместите свой UI в **Body**. Для дочерней вкладки поместите другой TabPanel
   (или готовый InventoryPanel/Workbench) в Body этой панели.
4. У **родителя** выберите **Side**: Top, Bottom, Left, Right. Это сторона полосы
   его непосредственных дочерних страниц. У каждого уровня своё значение.
5. При необходимости задайте **Initial Page**. По умолчанию выбирается первая
   доступная страница в порядке Hierarchy. **Available** исключает страницу из выбора.
6. Настройте внешний вид `TabButton.prefab` (Image, Text, Button), фон панели,
   ширину/высоту полосы у TabPanel и размеры закладок у TabStrip.

Полоса строится в runtime из дерева. В prefab сохраняются шаблоны и настройки,
а не копии сгенерированных кнопок. У листа полоса скрыта и не занимает место.
`Body` и `Tabs` — отдельные RectTransform: не помещайте свои предметы в Buttons.

Готовые `InventoryPanel`, `GunWorkbench`, `CampfireWorkbench` уже содержат фасад.
Они работают и самостоятельными корнями, и вложенными страницами. Данные предметов,
рецепты, фильтры и ссылки на PlayerContext по-прежнему настраиваются на их существующих
компонентах; TabPanel управляет только представлением.

## Процедурное создание и внешние события

```csharp
TabPanel page = Instantiate(pagePrefab); // prefab с настроенной Surface
page.Caption = "Содержимое сундука";
page.Icon = chestIcon;
page.AttachTo(parentTab);                // помещает в Body, обновляет дерево
page.Open();                             // открывает всю цепочку предков и выбирает страницу

parentTab.SelectChild(page);
page.Close();                            // дочернюю исключает из списка; корневую выключает
page.SetAvailable(true);                  // возвращает дочернюю в список без принудительного выбора
rootTab.Toggle();
```

`Open()`, `Close()`, `Toggle()`, `SetOpen(bool)` подходят для Inspector UnityEvent.
У фасада есть UnityEvent **On Shown / On Hidden**, C# `VisibilityChanged(bool)` и
`SelectionChanged(TabPanel)`. Событие видимости отражает также переключение предка
и закрытие корня. `SelectedPage`, `Children`, `Parent`, `IsVisible` доступны для чтения.

Для горячей клавиши добавьте игровое действие в MainInputProfile и установите
`GameActionListener` на **постоянно активный объект**. Укажите ID и свяжите
`On Performed → ваш корень / TabPanel.Toggle`. Слушатель на выключенном корне
не сможет открыть себя. В сцене примера действие Inventory.Toggle вызывает
WorldDemoControls, который открывает/закрывает оба корня одной командой.
Режим нажатия и привязки задаёт [InputSystem](InputSystem.md), UI не опрашивает клавиши.

Можно использовать `Instantiate(prefab, parent.Body)` или менять Transform вручную.
Прямое добавление/удаление и `AttachTo` обновляют дерево автоматически. После
пакетной перестройки промежуточных wrapper-объектов вызовите `RefreshHierarchy()`
на корне: так не нужен постоянный обход всей сцены каждый кадр. Порядок кнопок
следует Hierarchy; после программного `SetSiblingIndex` также вызовите RefreshHierarchy.
Попытка AttachTo собственного потомка отвергается.

## Жизненный цикл и сохранность предметов

1. При включении корня фасад собирает ближайшие дочерние страницы, затем их поддеревья.
2. `TabSelection<T>` сохраняет прежний выбор, если он ещё доступен. Иначе выбирает
   ближайшего доступного соседа; пустой набор не имеет выбранной страницы.
3. `TabStrip` создаёт/переиспользует кнопки, выделяет выбор и показывает его в scroll.
4. Страница получает размер Body родителя. Смена размера перестраивает раскладку.
5. Переключение страницы меняет `CanvasGroup.alpha/interactable/blocksRaycasts`.
   GameObject, InventoryView и модель остаются активны. Поэтому продолжают поступать
   обновления контекста/preview и сохраняется захваченный источник drag.
6. Скрытая страница не участвует в raycast; её InputField теряет клавиатурный фокус.
   Стандартный TabButton переключает страницу при наведении с активным pointerDrag.
7. Закрытие корня выключает его GameObject. Обычный OnDisable снимает UI-подписки
   и отменяет перенос; модель не уничтожается. Открытие восстанавливает выбранные страницы.

Для фоновой логики страницы не используйте OnDisable как сигнал её переключения —
подпишитесь на события фасада. Для удаления данных используйте API модели отдельно;
закрытие UI не означает удаление инвентаря или станции.

## Адаптивная раскладка

| Компонент | Назначение |
| --- | --- |
| `TabPanel` | Резервирует место для полосы на выбранной стороне, растягивает страницы в Body. |
| `TabStrip` | Горизонтальная/вертикальная прокрутка при переполнении, иконка и текст в каждой кнопке. |
| `ResponsiveColumns` | Независимые окна рядом либо вертикально в зависимости от ширины родителя. |
| `AdaptiveGridLayout` | Число столбцов от доступной ширины, квадратные ячейки, вычисляемая высота Content. |
| `DesignSizeLayout` | Сохраняет авторскую ручную композицию крафта и уменьшает её целиком при нехватке ширины. |
| `ScrollRect` + `ContentSizeFitter` | Доступ ко всем ячейкам/контролам при малой высоте окна. |

В инвентаре viewport занимает всю страницу; заголовок, сетка и подсказка находятся
в общем прокручиваемом content. Даже очень низкое окно не получает отрицательную
высоту viewport из-за фиксированных шапки/подвала. Изменяемое количество ячеек
увеличивает content по вертикали. Крафт-станция также прокручивается целиком:
диаграмма, рецепт, описание, кнопки и статус. В PlayerContext поля расположены строками
в прокрутке. Сохраняются отдельные настройки шрифтов, цветов и placeholder-ов.

Для ручной диаграммы редактируйте содержимое `RecipeDiagram/Design`, а её исходный
размер задавайте в DesignSizeLayout. Для других схем вместо него можно поставить
стандартные Unity LayoutGroup. Корни не получают принудительный масштаб от TabPanel.
CanvasScaler примера использует Constant Pixel Size со Scale Factor = 1: при малом
экране меняются расположение окон и число столбцов, а не только размер текста.
Можно изменить Scale Factor или режим CanvasScaler; layout ориентируется на размеры
родителей в координатах Canvas, без расчётов через Screen.width в Views.

## Миграция и проверки

Команда `Tools → Inventory → Upgrade to procedural tabs` добавляет фасады к старым
prefab-ам, перестраивает UI и подключает сцену. Существующие модели, рецепты, ID,
иконки, ссылки и GUID сохраняются. Уже мигрированные панели повторно не перевёрстываются.
Это миграция образца, а не обязательный runtime bootstrap.

Изменились пути UI-объектов внутри prefab-ов: теперь используется Body, а у станций
Scroll/Viewport/Content. Сериализованные ссылки компонентов сохранены; внешний код,
который использовал Transform.Find по старым строковым путям, нужно обновить.

Автотесты находятся в `Assets/Tests/Editor/Tabs` и существующем наборе Inventory.
Они проверяют выбор/удаление/переподчинение страниц, вложенные деревья, сохранность
модели, внешнее действие ввода, фокус, raycast, перенос через hover закладки,
переполнение полосы и раскладку при разных размерах. Scene-проверки входят в Editor
suite и явно переходят в Play Mode.

Проверка 2026-09-30, Unity 6000.6.3f1: полный прогон — **94/94**.
После окончательной адаптации прокрутки повторно прошли сценарии Inventory/крафта
и World, затем **7/7** проверок вкладок, включая добавленную проверку действия
Inventory.Toggle в Test.unity. Внешний вид проверен при 1280×800, 1920×1080,
800×1100 и 640×480; отдельно проверен родитель 340×260 с масштабом 0.75,
все стороны полосы и переполнение 16 дополнительными страницами. Проверки
выполнены в изолированной копии; в основной проект перенесены проверенные assets.
