# Игровые действия и переназначение управления

В `Assets/Scenes/Test.unity` меню открывается клавишей **F1** или кнопкой
**«Управление»** справа сверху. Кнопка остаётся доступной даже после снятия
горячей клавиши самого меню.

Нажмите привязку в строке действия, отпустите уже удерживаемые клавиши и нажмите
новую. Поддерживаются клавиатура, отдельные кнопки мыши и два направления колеса.
`Escape` тоже можно назначить; для отмены захвата есть кнопка **«Отмена назначения»**.
Кнопка **«Снять»** очищает привязку, **«По умолчанию»** восстанавливает весь каталог.
Изменения сохраняются автоматически. Прокрутка работает при любом количестве строк.

## Кто за что отвечает

```text
Unity Input → IInputSource → BindingTable → GameInputAction.Performed → реакции игры
                                           ↑
                          GameActionDefinition (ID + Press/Hold)
```

| Часть | Назначение |
|---|---|
| `GameInputProfile` | Авторский ScriptableObject: список ID, подписей, категорий, режимов и defaults |
| `GameActionDefinition` | Описание одного действия; его ID не зависит от физической клавиши |
| `InputBinding` | Одна клавиша/кнопка либо направление колеса; режима реакции здесь нет |
| `BindingTable` | Единственный алгоритм разрешения конфликтов для Editor и runtime |
| `GameActionRouter` | Читает привязки, применяет режимы, выполняет события и блокировки |
| `GameInputAction` | Стабильное событие `Performed`; объект и подписчики сохраняются при rebind |
| `RebindCapture` | Захват следующего ввода, ожидание отпускания начального click, отмена |
| `IInputSource` / `LegacyInputSource` | Подменяемый источник ввода / backend существующего Unity Input Manager |
| `InputManager` | Unity lifecycle, профиль, capture, сохранение, общая точка доступа |
| `IBindingStore` / `PlayerPrefsBindingStore` | Подменяемое хранилище / локальные пользовательские настройки |
| `InputHandler` | Владение обычными подписками на игровые действия |
| `InputContext`, `InputContextChain`, `InputContextManager` | Контекстные реакции, двусвязная цепочка и Unity-владелец корня |
| `GameActionListener` | Связывает ID действия с UnityEvent в Inspector без нового класса |
| `InputSettingsView`, `InputBindingRowView` | Меню и шаблон его строки, без собственной логики конфликтов |
| `InputUiGate` | При наборе текста в UGUI InputField игровые действия не выполняются |

Универсальная механика находится в `Assets/Shared/Scripts/Systems/InputSystem`.
Конкретное меню — в `Assets/Scripts/Input`, его данные — в `Assets/Data/Input`,
префабы — в `Assets/Prefabs/Input`. Это соответствует обязательным критериям
из `project_context.md`: Shared не ссылается на Game, сцену или её конкретные команды.

## Добавить игровое действие через Editor

1. Откройте `Assets/Data/Input/MainInputProfile.asset`.
2. Добавьте элемент кнопкой `+`. Она создаёт уникальный ID и пустую привязку.
3. Назначьте постоянный смысловой **Id**, например `Light.Toggle`, **Display Name**
   и при необходимости **Category**. ID используется кодом и сохранёнными настройками;
   изменение подписи безопасно, переименование ID требует миграции его потребителей.
4. Выберите **Trigger**: `Press` или `Hold`.
5. Настройте **Default Binding**: `Key` и KeyCode либо `WheelUp` / `WheelDown`.
   `Key / None` означает отсутствие привязки. Если control занят, прежняя строка
   становится `None` сразу, в том числе при назначении в более раннюю строку списка.
6. На активный GameObject добавьте `GameActionListener`, скопируйте ID в `Action Id`
   и настройте `On Performed` как обычный UnityEvent. Можно назначить InputManager
   явно или использовать экземпляр сцены. Сам объект-слушатель должен оставаться
   активным, если событие включает другую, пока выключенную панель.

При следующем запуске новая строка появится в меню автоматически. Ни enum действий,
ни switch по их видам, ни изменения классов меню не нужны. Просто добавление записи
не изобретает игровую реакцию — её задаёт UnityEvent либо код-подписчик.

Каталог фиксируется для текущей сессии при `InputManager.Initialize`. Авторские
изменения списка/режимов выполняйте до Play Mode; пользовательские привязки во время
игры меняйте через меню или `Rebind`. Правка defaults в asset не перезаписывает
сохранённую раскладку игрока; для применения defaults нажмите сброс в меню.

## Нажатие и удержание

`Press` выполняется один раз в кадр начала нажатия. `Hold` выполняется каждый tick,
пока control удерживается, **включая первый кадр**. Отдельного длительного ожидания
перед Hold нет. Для движения с постоянной скоростью реакция должна учитывать deltaTime.
Колесо мыши даёт импульс в каждом кадре ненулевой прокрутки; Hold на колесе выполняется
в такие кадры. Переназначение колесо → клавиша не меняет Trigger.

В тестовой игре вращение камеры Q/E использует Hold. Действия приближения/отдаления удалены; колесо остаётся доступным интерфейсу.
Открытие инвентарей, настройки и отмена переноса также проходят через игровые действия.
Pointer drag и стандартная навигация UI остаются жестами EventSystem; они не становятся
произвольно переназначаемыми последовательностями кнопок в этом слое.

## Конфликт привязок

Во всём каталоге действует правило **один control — одно действие**. Например,
при назначении Q действию «Повернуть вправо» у «Повернуть влево» устанавливается None.
Сначала меняются обе записи, затем отправляется уведомление, поэтому UI и подписчики
не наблюдают промежуточного дубликата. Правило одинаково для клавиатуры, мыши и колеса.
Несколько реакций на *одно действие* при этом разрешены: это обычные подписчики события.

`GameInputProfile.OnValidate` использует ту же BindingTable и отслеживает изменённую
строку. Undo возвращает обе привязки. Для изначально неоднозначных импортированных
данных без истории изменений приоритет получает последняя строка. Пустые/повторяющиеся
ID показываются ошибкой Inspector; runtime отвергает такой каталог при инициализации.

## Подключение в коде

```csharp
// Подписка остаётся действительной после переназначения клавиши.
IDisposable subscription = InputManager.Instance
    .GetAction("Light.Toggle")
    .Subscribe(ToggleLight);

// Снимает чужую привязку F, если она была.
InputManager.Instance.Rebind("Light.Toggle", new Shared.Inputs.InputBinding(KeyCode.F));

// Например, в OnDisable владельца реакции.
subscription.Dispose();
```

`GetAction` возвращает null для неизвестного ID; проверяйте конфигурацию, если ID
приходит извне. Не храните копию клавиши в реакциях игры: читайте `GetBinding(id)`
для актуальной подписи подсказки. `WorldDemoControls` делает именно это.

Для контекстной реакции добавьте `new InputAction("Light.Toggle", ToggleLight)` в
`Actions` наследника `InputContext`. Сигнал сначала обходит контексты от вершины к
корню. Первый обработчик, вернувший true, поглощает его. Необработанный сигнал
доходит до обычных подписчиков `GameInputAction.Performed`, включая `GameActionListener`.
Обработчик из списка Actions всегда поглощает своё действие. Клавиши остаются в
профиле: новый контекст не создаёт вторую привязку той же клавиши.

Цепочка доступна через `InputManager.Instance.Contexts`. Её `Root` и `Current`,
а также `InputContext.Previous/Next` доступны только для чтения. Вход возвращает
дескриптор конкретного узла:

```csharp
private System.IDisposable contextLease;

void OpenMode()
{
    contextLease = InputManager.Instance.Contexts.Enter(
        new InspectContext(InputManager.Instance));
}

void CloseMode()
{
    contextLease?.Dispose();
    contextLease = null;
}

sealed class InspectContext : InputContext
{
    public InspectContext(Shared.Inputs.IGameActionSource source) : base(source)
    {
        Actions.Add(new InputAction("Inspect.Rotate", Rotate));
    }
    private void Rotate() { /* Реакция режима; действие объявляется в профиле. */ }
    public override bool TryHandleScroll(UnityEngine.Vector2 delta)
    {
        // Обработать жест интерфейса независимо от пользовательской привязки камеры.
        return true;
    }
}
```

Освобождайте дескриптор в OnDisable/OnDestroy владельца. Повторный Dispose безопасен.
Закрытие промежуточного узла снимает также всех потомков; старый дескриптор не
закроет новый режим. `Pop()` снимает вершину, но не корень. `Dispose()` самой
цепочки освобождает всё. Уже обработанный сигнал не повторяется после перехода.
Экземпляр контекста используется один раз, повторный вход требует нового объекта.

Жизненный цикл: Init → OnEntered → OnBecameCurrent; при перекрытии вызывается
OnCovered, при возврате — снова OnBecameCurrent. При освобождении вызывается
OnExited. Новая инициализация выполняется до удаления старого корня, поэтому
ошибка входа не оставляет приложение без ввода. Менять цепочку из этих lifecycle
callbacks нельзя; переходы выполняются из обработчиков действий/владельца.

Переопределяйте `TryHandleAction`, если нужна условная передача вниз. При
переопределении вызывайте base для стандартных Actions и Cancel, если они нужны.
Наследник может поглотить действие без реакции — так окно блокирует приближение.
Для будущего режима Ctrl/Shift вход выполняется по нажатию, освобождение токена —
по отпусканию; адаптер модификаторов в текущий пример не включён.

### Колесо и инвентари

`IScrollInputSource` — необязательный контракт точной величины прокрутки. Router
сначала предлагает жест контекстам, затем выполняет привязанные действия только
для непоглощённого колеса. Для старых IInputSource остаются импульсы ±1.
Таким образом, прокрутка UI сохраняется независимо от игровых привязок. Текущая камера колесо не использует.

`InventoryInputCoordinator` на InventoryDemo следит за корневыми TabPanel:
первое открытое окно добавляет контекст, последнее закрытое освобождает его.
Переключение дочерних страниц не меняет уровень контекста. Открытое окно поглощает
колесо и перечисленные в Inspector Blocked Actions. Вне панели колесо не влияет
на камеру; внутри прокручивается верхняя панель под курсором.

Если на сцене несколько таких prefab-ов, их координаторы регистрируются в
общей InventoryInputSession для одной InputContextChain. Количество окон
не добавляет лишних уровней. Сессия удаляется после отключения последнего
координатора. Скрытие корня источника отменяет перенос даже при других открытых окнах.

При переносе добавляется третий контекст. Колесо меняет выбранное количество,
Cancel отменяет перенос; следующая отмена закрывает окна. Inventory.Toggle и
Settings.Input проходят вниз. Закрытие окна во время переноса отменяет его.
`ContextScrollRect` получает прокрутку от координатора, а автоматическое событие
EventSystem игнорирует: один сигнал выполняется ровно один раз.

Для собственной группы окон добавьте один InventoryInputCoordinator на общего
родителя под Canvas, задайте Windows (пустой список находит корни в дочерних
объектах при OnEnable) и используйте ContextScrollRect вместо ScrollRect.
Рабочий InputManager и корень цепочки должны существовать на сцене. Без них
ContextScrollRect сохраняет стандартную прокрутку UI.

### Миграция контекстов v1

Список Actions и вызовы SetRootContext/AddContext/EscapeContext сохранены;
AddContext теперь возвращает IDisposable. Запись в Previous/CurrentContext
заменяется операциями цепочки. Защищённые Subscribe/Unsubscribe и поле
_contextManager больше не используются: контекст обрабатывает TryHandleAction
до обычных подписок. Init и OnEscape сохранены, освобождение переносится в OnExited.
Activate/Deactivate оставлены для совместимости обычных Actions, но не управляют
подписками. Для нового кода используйте вход и освобождение дескриптора.

Для модального окна используйте `using`/`Dispose` токена `InputManager.Suspend()`.
Блокировки вложенные: закрытие одного окна не снимает блокировку другого. Условный
запрет подключается через `AddGate(Func<bool>)`, который тоже возвращает токен.
Для другого поля ввода/другого UI toolkit можно добавить такой gate вместо изменения core.

## Жизненный цикл захвата

1. `InputManager` создаёт router из каталога и накладывает сохранённые привязки.
2. Менеджер устанавливает корень контекстов; GameActionListener подписывается на стабильные игровые действия.
3. При открытии меню создаются строки из каталога и берётся токен блокировки игры.
4. «Назначить» запускает RebindCapture. Уже удерживаемые клавиши и click открытия
   должны сначала отпуститься; только следующее новое нажатие назначает control.
5. Во время capture кнопки назначения/снятия блокируются, работают отмена и закрытие.
   Click по кнопкам UI не назначает Mouse0. Для назначения мыши нажмите на свободном
   фоне меню. Return/Space не вызывают одновременно Submit кнопки UI.
6. После назначения BindingTable снимает конфликт, настройки сохраняются, UI обновляется.
   Нажатие назначения не выполняет игровую реакцию.
7. При закрытии, отмене или потере фокуса незавершённый capture отменяется. После
   возврата к игре требуется нейтральный ввод: удерживаемая кнопка закрытия не играет действие.

## Настройка внешнего вида и подключение к другой сцене

`Assets/Prefabs/Input/InputSettingsMenu.prefab` — обычный UGUI prefab. Активный корень
содержит Canvas и кнопку открытия, а `Dialog` с InputSettingsView первоначально выключен.
Меняйте размеры, цвета, шрифты, подписи, фон и расположение footer в Prefab Mode.
`Scroll/Viewport/Content` содержит VerticalLayoutGroup и ContentSizeFitter, ScrollRect
и scrollbar отвечают за переполнение. Не заменяйте этот content фиксированным списком строк.

`Assets/Prefabs/Input/InputBindingRow.prefab` — отдельный шаблон. Его можно заменить
своим prefab с InputBindingRowView, назначив Text/Button-ссылки. Меню создаёт по одной
строке на определение; код не знает их заранее.

Для другой сцены нужны InputManager с GameInputProfile и EventSystem с
StandaloneInputModule (в текущем проекте используется старый Unity Input Manager).
Положите prefab меню в сцену. Для горячей клавиши добавьте GameActionListener на
активный объект и свяжите `Settings.Input` → `Dialog/InputSettingsView.Open`.
Добавьте InputUiGate, если на сцене есть UGUI-поля для набора текста.
Универсальному InputManager не нужны ссылки на CameraManager, WorldState или меню.

## Хранение и тестирование

Пользовательский JSON хранится в PlayerPrefs по ключу `input.bindings.v1.<ProfileId>`.
Он содержит только версию, ID действий и bindings. Режимы/реакции там отсутствуют.
Профили должны иметь разные ProfileId, если им нужны независимые настройки.
Сохранённые назначения имеют приоритет над defaults, в том числе над появившимися
позже действиями. Неизвестные ID и неподдерживаемые controls пропускаются.
Повреждённый JSON даёт предупреждение и defaults. Сохранение не меняет ScriptableObject,
сцену или сетевой WorldState.

Core тестируется с IInputSource без настоящего нажатия клавиш и загрузки сцены.
`InputCoreTests` проверяет exclusivity, Editor/Undo, Press/Hold, блокировки, захват,
сохранение и стек контекстов. `InputSettingsPlayTests` проверяет готовую сцену, вызов
меню через действие, строки, реальное переполнение ScrollRect, переназначение,
возврат defaults, повторное открытие и доступ кнопкой без горячей клавиши.

Проверено 2026-09-30 в Unity 6000.6.3f1: **88/88** тестов проекта прошли,
включая 13 проверок нового слоя ввода и меню. Scene-тест входит в Editor suite,
но явно запускает Play Mode через `EnterPlayMode`. Дополнительно проверен внешний
вид меню при 1280×720. Прогон выполнен в изолированной копии проекта; проверенные
profile, prefab-ы и `Test.unity` перенесены в основной проект с сохранением GUID.

## Миграция прежнего API (слой действий v2)

GUID существующих MonoBehaviour сохранены. Скрытые `keyActions`, `scrollUpEntries`,
`scrollDownEntries` оставлены как мост сериализации старых сцен: если Profile не задан,
из них создаётся временный каталог с прежними ID. Он не сохраняет настройки пользователя.
В `Test.unity` уже назначен новый профиль; старые поля больше не управляют вводом.

API реакции изменён явно: вместо физического `IInputAction/KeyAction/ScrollAction`
с `OnPressed/OnHeld/OnReleased` используется `GameInputAction.Performed` и режим в
GameActionDefinition. `InputAction` контекста принимает один `onPerformed`.
Обработчики конкретной игры перенесены с `Q/E/ScrollUp/ScrollDown/Esc` на
`Camera.RotateLeft/Camera.RotateRight/Cancel`.
Для своих старых подписчиков перенесите выбор Press/Hold в профиль и подпишитесь на
Performed; требующий отдельной семантики release сценарий должен получить осмысленное
расширение режима, а не скрытую свободу пользователя менять принцип реакции.

Однократный инструмент `Tools → Input → Set up input actions and settings` создаёт
исходные assets и подключает Test.unity. Он сохраняет существующие profile/prefab-ы.
Обычное расширение после настройки делается в Inspector, без повторного запуска сборщика.
