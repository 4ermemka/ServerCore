# GridSystem: настройка, запросы и расширение

`Assets/Shared/Scripts/Systems/GridSystem` строит статическую многоуровневую сетку
по физическим поверхностям сцены. Каждая ячейка — отдельный GameObject; связи между
ними образуют направленный граф. Система предоставляет выбор ячеек, поиск ближайшей,
обход соседей и поиск пути. Перемещение персонажа, занятость клеток и стоимость
переходов остаются логикой игры.

Привязка Player/Furniture к данным мира и перенос курсором описаны в
[WorldObjects.md](WorldObjects.md). Для разрешения сохранённого адреса используется
перегрузка `GridProvider.GetCellAt(Vector3Int gridPosition)`: она возвращает реальную
ячейку, включая точную высоту её поверхности, без пересчёта через мировые координаты.

## С чего начать в существующем проекте

В `Assets/Scenes/Test.unity` уже есть `GridProvider`, `GridGenerator` и сохранённые
ячейки. Найдите генератор, проверьте ссылки и нажмите **Generate Grid** в Inspector.
**Clear Grid** удаляет ячейки из выделенного контейнера. В редакторе обе операции
поддерживают Undo; сохраняйте сцену после нужных изменений. Автоматической генерации
при запуске Play нет: используется сохранённая сетка либо явный вызов `GenerateGrid()`.

После обновления начало координат генерации задаёт **GridProvider**, а позиция
объекта `GridGenerator` не влияет на сетку. Ранее генератор и провайдер могли считать
координаты относительно разных объектов. Если они были смещены относительно друг
друга, пересоздайте сетку. Сцену и уже сохранённые ячейки эта правка сама не пересоздаёт.

## Компоненты

| Компонент | Назначение |
| --- | --- |
| `GridCell` | Координаты, точная высота, ориентация по нормали, флаг валидности, сериализованный список соседей, события указателя. |
| `GridProvider` | Индексы по XYZ и колонкам XZ, регистрация/удаление ячеек, запросы, события всей сетки. Наследуется от `Manager`. |
| `GridGenerator` | Поиск поверхностей лучами, создание объектов, выбор соседей и очистка. |
| `IGridCell` | Общий контракт ячейки. `GridCell.GetWorldPosition()` возвращает фактический `transform.position`. |
| `IGridProvider` | Контракт запросов и событий. |
| `IPathFinder<T>` | Контракт поиска пути; `GridProvider` реализует его для `GridCell`. |
| `GridGeneratorEditor` | Кнопки Generate/Clear, отображение связей, восстановление индексов после Undo/Redo. Файл находится в `Assets/Editor/Grids`. |

Смежные компоненты:

- `Selectable` отвечает за материалы выделения. Его ссылка кэшируется в ячейке.
- `SelectionTypeManager` загружает определения выделений из `Resources/SelectionTypes`.
- `GridSelector` в `Assets/Scripts/DebugAndTest` демонстрирует Hover, Neighbour и Click.
  Его `Init()` вызывается через инфраструктуру менеджеров; подписки снимаются при уничтожении.
- `GridMovementManager.MoveTo` просто устанавливает позицию объекта в центр ячейки.
  Это телепортация, без анимации, поиска пути или проверки коллизий.
- `GridOverlay` — отдельный инструмент отображения линий в Scene View. Он не создаёт
  `GridCell` и не задаёт параметры `GridProvider`.

## Создание новой сетки

1. Подготовьте геометрию под объектом `Surfaces`. Нужны активные включённые 3D
   Collider: `Renderer` не обязателен. Триггеры не участвуют в генерации.
2. Создайте `GridRoot` с `GridProvider` и отдельный пустой контейнер `Cells`.
   Назначьте его в `GridProvider.Cells Container`. Настройте `Cell Size`.
3. Подготовьте prefab ячейки с `GridCell`. Unity добавит `Selectable` и требуемый
   `MeshRenderer`. Для отображения добавьте геометрию/материал, для кликов — Collider.
   Prefab-источник храните в Project, вне контейнера генерируемых ячеек.
4. Создайте объект с `GridGenerator`. Назначьте `Targets Container = Surfaces`,
   `Grid Holder = GridRoot`, `Cell Prefab` и тот же `Cells Container = Cells`.
   Контейнеры поверхностей и ячеек должны находиться в отдельных ветках иерархии.
5. В `Scan Layer Mask` включите слои поверхностей. Слой визуальных ячеек исключите
   из сканирования и проверки препятствий, чтобы их коллайдеры не влияли на генерацию.
6. Настройте параметры ниже, нажмите Generate Grid, проверьте уровни и связи в Scene View.
   При ошибке ссылок, отсутствии подходящей геометрии или превышении лимита сканирования
   прежняя сетка сохраняется. Clear Grid удаляет именно `GridCell`, а не все дочерние
   объекты контейнера; вспомогательные объекты без GridCell остаются.
7. Для событий указателя нужны EventSystem, подходящий модуль ввода и
   `PhysicsRaycaster` на камере. Маска лучей камеры должна включать слой ячеек.
   Сам `GridCell` не создаёт эту инфраструктуру.

Рекомендуемая иерархия:

```text
World
├── Surfaces                 ← коллайдеры исходной геометрии
├── GridRoot + GridProvider   ← начало координат XZ и CellSize
│   └── Cells                ← сгенерированные GameObject-ы
└── GridGenerator            ← ссылки на Surfaces, GridRoot, Cells и prefab
```

`GridProvider` работает и без `ManagersHolder`: первый запрос и `Start` лениво
восстанавливают индекс. Для использования `GetManager<GridProvider>()` и
`GridMovementManager` включите провайдер в список менеджеров проекта.

## Параметры генерации

| Поле | Что означает |
| --- | --- |
| `Cell Size` у провайдера | Положительный конечный шаг сетки в мировых единицах. |
| `Height Offset` | Смещение ячейки вверх от точки попадания, в мировых единицах. Помогает избежать наложения визуала на пол. |
| `Vertical Merge Threshold` | Минимальное расстояние между принятыми поверхностями одной колонки: значение умножается на CellSize. Сканирование идёт сверху вниз. |
| `Neighbor Height Threshold` | Максимальная разница фактических высот соседей; тоже умножается на CellSize. |
| `Scan Layer Mask` | Коллайдеры для нисходящих лучей. После луча дополнительно проверяется принадлежность Targets Container. |
| `Max Slope Angle` | Максимальный угол поверхности относительно горизонтали, от 0 до 90 градусов. |
| `Min Clearance Height` | Длина проверки вверх от точки поверхности с учётом Ray Offset; 0 отключает проверку. |
| `Clearance Check Radius` | Радиус восходящего SphereCast; при 0 используется обычный Raycast. |
| `Clearance Ray Offset` | Насколько выше точки попадания начинается проверка свободного места. |
| `Obstacle Layer Mask` | Слои потолков/препятствий. Значение Nothing/0 означает использовать Scan Layer Mask, а не отключить проверку. |
| `Max Scan Columns` | Лимит прямоугольной области XZ, по умолчанию 1 000 000 колонок. Превышение отменяет генерацию до удаления старых ячеек. |

Границы берутся по подходящим **коллайдерам**, а не по Renderer. В каждой колонке
выполняется луч сверху вниз. Общий буфер попаданий увеличивается при заполнении,
поэтому фиксированного ограничения в 10 поверхностей больше нет. Попадания
сортируются по высоте и фильтруются; близкие уровни объединяются. Если две поверхности
округляются в одинаковый XYZ-ключ, сохраняется первая допустимая верхняя поверхность.

Проверка свободного места сохраняет прежний принцип: учитывает первое препятствие
при движении вверх, игнорируя поддерживающий коллайдер. Это не полная проверка
объёма персонажа. Если пол и потолок объединены в один сложный Collider, такой
фильтр может быть недостаточен; для точной навигации добавьте свою проверку объёма.

## Координаты и соседство

Сетка ориентирована по **мировым XZ**. Вращение и scale объекта провайдера не
поворачивают и не масштабируют систему координат. При начале `origin = provider.transform.position`:

```text
grid.x = RoundToInt((world.x - origin.x) / CellSize)
grid.y = RoundToInt(world.y / CellSize)
grid.z = RoundToInt((world.z - origin.z) / CellSize)

world.x = origin.x + grid.x * CellSize
world.y = фактическая высота поверхности + HeightOffset
world.z = origin.z + grid.z * CellSize
```

Y-координата ключа — округлённый уровень относительно мирового нуля, а `WorldY`
содержит точную высоту на момент генерации. `GetWorldPosition(cellSize)` использует
Transform ячейки; параметр оставлен ради совместимости интерфейса. При ручном
создании отдельно назначайте `transform.position` и вызывайте `Initialize`.

Генератор рассматривает четыре соседние колонки: +Z, -Z, -X, +X. В каждой выбирает
созданную ячейку с ближайшим `WorldY` в допустимом пороге. При равной разнице
предпочитает более высокую из созданных поверхностей. Нет диагоналей, вертикальных
связей внутри одной колонки или проверки препятствия между центрами.

Связи **направленные**: A может выбрать B, а B — другой этаж той же соседней колонки.
Взаимность автоматически не добавляется. Для мостов, лестниц, односторонних спусков
или дверей настройте `SetNeighbors` самостоятельно либо расширьте генератор.
При отсутствии ячейки в соседней колонке перехода нет; через пустую колонку граф не прыгает.

Сетка рассчитана на статическую геометрию. После изменения CellSize, начала,
поверхностей или размещения ячеек выполните Generate Grid. `RebuildIndex` только
перечитывает сохранённые координаты и не пересчитывает их из Transform или соседство.

## Жизненный цикл

1. **Редактор:** генератор проверяет ссылки и размеры, синхронизирует трансформы с
   физикой, вычисляет границы. Затем очищает прежний индекс и ячейки.
2. **Генерация:** для поверхности создаётся экземпляр prefab-а, назначаются позиция,
   нормаль и `Initialize`. Ячейка регистрируется; после создания всех ячеек записываются соседи.
3. **Сохранение:** координаты, валидность и ссылки на соседей сериализуются вместе
   с объектами сцены. Словари и подписки не сериализуются.
4. **Загрузка / первый запрос / Init:** `RebuildIndex` находит активные GridCell в
   назначенном контейнере. В индекс попадают валидные ячейки с уникальным ключом.
   Даже пустая сетка считается загруженной и не сканируется повторно при каждом чтении.
5. **Работа:** словарь XYZ обслуживает точные запросы, индекс XZ — запросы области.
   События ячеек через постоянные посредники отправляются текущим слушателям провайдера.
6. **Изменение состава:** RegisterCell/RemoveCell инвалидируют снимок AllCells.
   Повторная регистрация того же ключа ничего не меняет. Одна ячейка может принадлежать
   одному провайдеру; регистрация в другом переносит её владение.
7. **Удаление:** GridCell.OnDestroy удаляет ячейку из её провайдера; удаление чужого
   дубликата с теми же координатами не затрагивает зарегистрированную ячейку.
   Уничтожение провайдера снимает его подписки со всех ячеек.
8. **Повторная генерация в Play:** старые объекты сразу выключаются, затем удаляются
   обычным Destroy в конце кадра. Они не участвуют в новых физических запросах;
   отложенное уничтожение старой ячейки не удаляет новую с тем же ключом.
9. **Undo/Redo:** Unity восстанавливает объекты/соседей, Editor-компонент перечитывает индексы.

`ClearAllCells()` очищает только данные провайдера и его подписки, сохраняя объекты.
После этого запросы не восстановят сетку сами: вызовите `RebuildIndex()` явно.
`GridGenerator.ClearExisting()` очищает данные и удаляет ячейки контейнера.

Простое отключение GameObject уже зарегистрированной ячейки не удаляет её из графа.
Для игрового запрета перехода используйте predicate пути, а для удаления из сетки —
RemoveCell. `Initialize(..., valid: false)` также снимет регистрацию. Прямые изменения
сериализованных координат/валидности в Inspector требуют `RebuildIndex`.

## Запросы и стоимость

N — число ячеек, C — число занятых колонок, V/E — посещённые вершины и связи.

| API | Результат и стоимость |
| --- | --- |
| `AllCells` | Кэшированный read-only список. Первое чтение после изменения состава: O(N) и создание снимка; повторные: O(1). Старый список не обновляется при добавлении/удалении ячеек; сами объекты в нём остаются живыми ссылками Unity. |
| `GetCellAt(world)` | Поиск округлённого XYZ-ключа, в среднем O(1). Это не проверка точки внутри Collider. |
| `GetClosestCell(world)` | Ближайший фактический центр в 3D, O(N), сравнение квадратов расстояний без создания списков. Пустая сетка даёт null. |
| `GetCellsInRadius(center, radius)` | Все этажи в ромбе XZ: `abs(dx)+abs(dz) <= ceil(radius/CellSize)`. Не проверяет достижимость. Создаёт выходной список. |
| `GetCellsInRadius(center, radius, result)` | Та же операция с переиспользуемым списком; сначала очищает его. Доступна у конкретного GridProvider. Обход выбирается между ромбом и всеми C колонками. |
| `GetNeighborsOfOrder(cell, order)` | Все достижимые за **не более** order рёбер, исходная исключена. BFS, O(V+E); не только внешнее кольцо. |
| `FindPath(start, end, predicate)` | BFS по зарегистрированным валидным ячейкам, кратчайший путь по числу переходов. O(V+E). Список включает start/end; при отсутствии пути null. |

Радиус 0 возвращает все этажи центральной колонки; небольшой положительный радиус
округляется вверх до одного шага. Отрицательный радиус даёт пустой список, NaN и
бесконечность отвергаются. Порядок элементов области не является контрактом API.
Отрицательный/нулевой порядок соседства даёт пустой список.

`FindPath(a, a, null)` возвращает одну зарегистрированную ячейку. `null` predicate
разрешает все связи. Predicate может проверять занятость, двери, навыки, но не должен
менять граф или уничтожать ячейки во время обхода. Внутренние буферы BFS локальны,
поэтому вложенный поиск из predicate не затирает состояние внешнего поиска.

## Примеры использования

Запросы и повторное использование буфера:

```csharp
using System.Collections.Generic;
using UnityEngine;

public class GridQueries : MonoBehaviour
{
    public GridProvider Grid;
    private readonly List<IGridCell> nearby = new();

    public void Inspect(Vector3 world)
    {
        IGridCell exact = Grid.GetCellAt(world);
        IGridCell closest = Grid.GetClosestCell(world);
        Grid.GetCellsInRadius(world, 3f, nearby); // прежнее содержимое очищается
        if (closest != null)
        {
            List<IGridCell> reachable = Grid.GetNeighborsOfOrder(closest, 2);
            Debug.Log($"В области: {nearby.Count}; за два перехода: {reachable.Count}");
        }
    }
}
```

Путь с дополнительным игровым запретом:

```csharp
GridCell start = provider.GetClosestCell(actor.position) as GridCell;
GridCell goal = provider.GetCellAt(clickedWorldPosition) as GridCell;
List<GridCell> path = provider.FindPath(start, goal,
    (from, to) => !occupiedPositions.Contains(to.GridPosition));
if (path != null)
{
    // Передайте path своей системе движения; GridProvider сам объекты не перемещает.
}
```

Для динамической блокировки такой predicate удобнее перегенерации всей сетки.
При неодинаковой цене переходов нужен отдельный алгоритм, например Dijkstra/A*,
с контрактом стоимости; текущий BFS минимизирует только число рёбер.

Подписка и ручное создание:

```csharp
provider.OnCellPointerClick += HandleClick;
// В OnDisable/OnDestroy владельца подписки:
provider.OnCellPointerClick -= HandleClick;

Vector3Int index = new(2, 1, 5);
float worldY = 1.25f;
GridCell cell = Instantiate(cellPrefab, cellsContainer);
cell.transform.position = provider.GridToWorldPos(index, worldY);
cell.Initialize(index, worldY, Quaternion.identity, true);
provider.RegisterCell(cell);
cell.SetNeighbors(new List<GridCell> { existingNeighbor }); // список копируется
```

Регистрируйте все узлы пользовательского графа в том же провайдере. После ручного
добавления связи при необходимости добавьте обратную отдельно. События на самих
ячейках оставлены Action-свойствами ради совместимости: используйте `+=`/`-=`,
не заменяйте их присваиванием, иначе можно стереть посредника провайдера.

## Что оптимизировано и что остаётся дорогим

- Повторное чтение AllCells больше не выполняет LINQ и копирование N элементов.
- Запросы области и графа обходятся без LINQ-итераторов; BFS соседства использует
  одну очередь вместо нового frontier-списка на каждом шаге и прекращается при её опустошении.
- GetClosestCell и отрисовка расстояний используют квадраты расстояний; исправлен
  преждевременный возврат округлённой, но фактически не ближайшей ячейки.
- Генератор не хранит списки всех попаданий для всех колонок. Буфер один, а связи
  ищутся среди созданных ячеек. Один временный список соседей используется повторно.
- Фильтр коллайдеров использует HashSet; проверка наклона сравнивает normal.y
  с заранее вычисленным косинусом. Неиспользуемый массив Collider удалён.
- Selection кэшируется. Пустой контейнер не сканируется при каждом запросе/Gizmos.
- UnityEditor-код закрыт `#if UNITY_EDITOR`, чтобы GridSystem компилировался для Player.

Генерация всё ещё выполняет физические запросы по прямоугольнику XZ и создаёт
GameObject на каждую ячейку. Selectable также создаёт материалы выделения. Для больших
миров следующий шаг — хранить граф отдельно от визуальных объектов, создавать видимые
ячейки по необходимости и делить генерацию на участки. В этой правке устройство
prefab-ов и сериализованный граф сохранены; таких крупных изменений нет.

## Проверка и типичные проблемы

| Симптом | Проверить |
| --- | --- |
| Нет ячеек | Collider, enabled/active, Scan Layer Mask, отсутствие Trigger, ссылки генератора. |
| Старые ячейки остаются после Generate | Сообщение в Console: невалидная конфигурация или превышен Max Scan Columns отменяют замену. |
| Ячейки есть, кликов нет | EventSystem, модуль ввода, PhysicsRaycaster, Collider ячейки и маски камеры; UI может перекрывать луч. |
| Ячейка в сцене, GetCellAt вернул null | Высота ключа, начало координат, CellSize, назначенный контейнер, IsValid и регистрация; для произвольной точки используйте GetClosestCell. |
| Радиус захватил другой этаж | Запрос области работает по XZ и включает все этажи. Для достижимости используйте GetNeighborsOfOrder. |
| Путь проходит сквозь стену | Соседство проверяет соседнюю колонку/перепад высоты, но не стену между центрами. Добавьте проверку ребра. |
| Путь существует только в одну сторону | Связи направленные; проверьте выбранные этажи и обратные соседства. |
| После ручных правок данные старые | RebuildIndex для индекса; Generate Grid для координат/геометрии/соседей. |
| Выделение не работает | Определения Hover/Neighbour/Click в Resources/SelectionTypes, материалы и завершение Start у Selectable. |

Тесты находятся в `Assets/Tests/Editor/Grid`, сборка `ServerCore.Grid.Tests` в
EditMode Test Runner. Они проверяют индексы, события, координаты, радиус, направленный
граф, многослойную генерацию, clearance, повторную генерацию, Undo/Redo и Play Mode.
Проверка 1000 повторений AllCells + ближайшая ячейка + запрос области в готовый буфер
после прогрева требует **0 байт управляемых выделений**; это не замер времени на вашей
полной сцене и не означает, что сама генерация или поиск пути ничего не выделяют.
