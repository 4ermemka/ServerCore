# Разделение типов и Editor-логики — 2026-11-04

Запрос: в обоих проектах вынести модели/DTO, records, extensions, контракты, Editor-логику в отдельные файлы и тематические подпапки системы. Существующие API, namespace, сериализованные имена и игровое поведение сохраняются.

Порядок: снимок исходников и Roslyn-инвентаризация; разборка независимых Shared-систем и прикладного кода; вынос вложенных типов через partial при необходимости сохранения API; отделение Editor-частей без пересечения границ partial-типов между сборками; обновление справочников и правил; семантическое сравнение деклараций, Unity полный EditMode/PlayMode suite, проверка ссылок/meta и независимое ревью.

Папки создаются по назначению, а не ради пустого шаблона: DTO, Models, Contracts, Events, Extensions, Configuration, Editor/EditorSupport, Contexts. DTO — переносимые данные; behavior-rich runtime-модели — Models; данные Inspector — Configuration. Вложенные public/serialized-типы не становятся top-level только ради файла.

Статус: рефакторинг завершён и автоматически проверен. Машинные снимки/результаты — ignored .utmp/CodeOrganization. Рабочий материал сохранять до явного подтверждения пользователем работоспособности.

Результат: 192 исходных C# файла разложены в 320 файлов, сохранены все 306 Editor / 292 Player type identities. DTO, модели, контракты, события, конфигурации, правила/фабрики, Extensions, nested helpers и generic-базы имеют свои файлы в системе-владельце. Main Unity scripts сохраняют имена, поля и GUID. Вложенные типы вынесены через partial без изменения API. Сетка/выделение получили EditorSupport под UNITY_EDITOR; чистые OnValidate — Validation. Только GridGenerator/GridProvider получили optional partial bridges; точное разворачивание хелперов совпадает с исходными телами методов в обеих ветках препроцессора.
