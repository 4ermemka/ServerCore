# Процесс и завершение

1. Прочитать project.md, packaging.md, соответствующие главы PROJECT/SHARED и активный материал в work, если он относится к задаче.
2. Проверить status обоих репозиториев. Определить владельца системы и compile boundary до нового файла.
3. Обновлять код и справочник вместе; проверять ссылочные переходы между системами и Shared.
4. Выполнять релевантные проверки поведения и Unity import/compile. Для структурной уборки проверять GUID, asmdef,
   пути загрузки и отсутствие потери файлов. Для моделей — snapshot/patch/JSON; для сети — Host/Client/Stop/reconnect;
   для UI — PlayMode и lifecycle. Не объявлять непроведённую проверку успешной.
5. Проверить итоговый diff, включая Shared, scene/prefab YAML, package lock и отсутствие generated output.

## Временные материалы

Планы, design notes, промежуточные исследования и отчёты конкретной незавершённой системы размещать только в
`.agents/context/work/<system-or-task>/` (для короткой задачи допустим один файл в work).
Это правило переопределяет стандартные пути docs/superpowers любых workflow-навыков.
Перед завершением перенести полезные решения, API, настройку и ограничения в оба постоянных справочника.
Успешные автоматические тесты сами по себе не разрешают чистить рабочие материалы.
После явного подтверждения пользователем работоспособности системы удалить только относящиеся к ней временные материалы;
остальные активные работы сохранить. Не очищать work целиком и не считать молчание подтверждением.
Текущая разовая уборка старых plans/specs прямо разрешена запросом от 2026-11-04; это не общее разрешение для будущих задач.
Логи и машинные результаты проверок хранить в ignored `.utmp`, не в developer-справочнике и не среди исходников.
